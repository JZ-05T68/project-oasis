## 按钮审计

- **多帐篷 Bug 根因**：事件 Modal 的高度上限（旧 `max-height: 85vh`）与 `.modal-body`
  的滚动裁剪叠加后，位于折叠线以下的帐篷按钮**落在滚动容器的裁剪区之外**，
  `elementFromPoint` 命中 `.modal-backdrop` —— 真人试玩看到的「前两顶能点、后两顶点不动」。
- **修复方式**：
  1. Modal `max-height: min(88vh, 100%)` + `.modal-backdrop` padding 收敛 → Modal 永不超出视口；
  2. 逐顶帐篷选项改紧凑行布局（选项列表高度压到约 1/3）；
  3. 内容仍溢出时**必须**显示可点击的「↓ 下方还有选项」滚动提示条；
  4. 规则页确认按钮移出滚动区；
  5. **帐篷改用稳定唯一 ID**（`tent-001`…）：引擎/UI 只传 `tentId`，绝不传 array index，
     新增 `TENT_REQUIRED` / `TENT_NOT_FOUND`；帐篷被消耗/报废导致列表重排也不会选错。
- **4 顶帐篷测试**：
  - 引擎侧 `tests/tentSelection.test.ts` + `tests/feedback.test.ts`：A/B/C/D 在
    沙尘暴 / 草原暴雨 / 野外宿营（矿区等待、绿洲停留同理）逐顶选择，每次都只消耗被选中的那一顶；
  - 浏览器侧 `storm`（28 项）、`rain`（18 项）、`stormlabels`（47 项）、`stormlabels2`（64 项）。
- **其他发现的问题**（均已修）：
  1. 网页「使用帐篷」按钮文字可能被裁（追加问题 2，见下）；
  2. 天气预报卡片方位错乱（追加问题 1，见下）；

## 地图布局

- **左黑边根因**：地图容器沿用了旧 `10×12` 布局的**固定尺寸**——
  `.grid-map { min-width: 420px }`（= 12 列 × 34px 最小格宽 + 间隙的硬编码）、
  `.grid-tile { min-width/height: 34px }`、`.grid-scroll { max-height: 62vh }`。
  缩到 9 列后这些数值不再成立。另外实测还发现一个**隐藏的居中 bug**：
  容器 `max-height` 作用在 border-box 上而自身有 1px 边框，会让地图比可视区高出约 2px →
  容器出现纵向滚动条 → 可视宽少 15px → **地图中心相对面板中心偏移 7.5px**。
- **修复方式**：容器不再有任何固定尺寸；
  宽度 = `min(容器宽, (可用高度 - 8px) × 列数 / 行数)`，行列数从 `gameConfig.map` 派生；
  容器高度改为 `calc(--map-max-h + 2px)` 抵消自身边框；`margin: 0 auto` 在自己的区域内居中；
  地图区与右侧日志各占 `.game-layout` 的独立轨道（日志宽度变化不会牵动地图中心）。
- **1366×768**：左右留白 142.7px / 142.8px，格子 61.6×61.6，中心偏差 **0px**，无横向溢出。
- **1920×1080**：左右留白 87.8px / 87.8px，格子 73.8×73.8，中心偏差 **0px**。
- **窄窗口**：1024×768 → 7.2 / 7.3；900×700 → 147.3 / 147.3；640×700 → 均对称，中心偏差 0。
- **地图居中**：9 组视口 × 缩放（1366×768、1518×853@90%、1242×698@110%、1920×1080、
  2133×1200@90%、1745×982@110%、1024×768、900×700，共 154 项断言）中心偏差全部为 0，
  且地图整图完整可见、不覆盖 HUD 与日志、格子保持接近正方形、合法移动高亮可点。

## 已知问题

1. **经济标定工具链**：`--workers 8` 时 worker 子进程会在跑到约 12000 局后不再退出，
   导致标定整体挂住（已确认不是某个 Seed 的死循环：单进程跑 ReasonablePlayerBot 正常）。
   已加「每分片 120s 看门狗」（超时杀子进程 + 跳过该片 + 明确报告跳过清单），
   `--workers 4` 下 9600 局正常跑完。3000×8 的规模本轮未跑满。
2. **定价规则的次准则**（上一轮记录，本轮未修改）：因负风险地形（村庄 -3.5 / 绿洲 -2.5）
   会被同长度次准则优先选中，更长的往返有时被评为「更不危险」，远端矿区不再必然更值钱。
3. **一次行动可能出现连续两条结算**（例如「野外宿营完成」+ 当天天气事件的结算），
   按事件发生顺序 FIFO 依次确认，并在按钮上提示「还有 N 条」。若真人试玩觉得啰嗦，
   下一轮可以合并为一条。
4. **沙尘暴按钮文字裁切**在修复前的当前代码里，于 1366×768 / 1920×1080 / 窄窗口 /
   640 极窄共 9 组视口下**无法复现**（实测 10 个按钮均无裁切）。因此按"预防性加固 + 逐视口
   持续断言"处理，并修掉了两个真实隐患（见「追加问题 2」）。

# 追加问题 1：天气预报邻域排列错误

**问题**：预报 Modal 的格子坐标本身正确，但卡片是按数组顺序塞进 3 列网格的。
地图边缘会裁掉越界方向（玩家在 `(7,0)` 时缺 `W / SW / S`），剩余卡片顺着网格
**自动向前补位**，于是 `(7,1)` 被挤到第三行，视觉方向与真实地图方向不一致。

**修复**：
- 引擎在 `ForecastCell` 上直接下发 `dr` / `dc`（相对玩家的行/列偏移，取值 `-1 / 0 / +1`），
  UI **只看 (dr, dc)，绝不看数组下标**；
- 渲染用固定 3×3 网格 + 显式 `grid-row = dr + 2` / `grid-column = dc + 2` 定位；
- 越界方向**直接不渲染元素**，空出来的行列保持为空 → 物理上不可能发生补位；
- 方位映射：`(-1,-1) 西北 / (-1,0) 北 / (-1,+1) 东北 / (0,-1) 西 / (0,0) 当前格 /
  (0,+1) 东 / (+1,-1) 西南 / (+1,0) 南 / (+1,+1) 东南`；
- 布局规模：内部 `3×3`、上/下边缘 `2×3`、左/右边缘 `3×2`、四角 `2×2`；
- 卡片内容不变（方位名 + 坐标 + 地形/未知 + 天气 + 当前格标识）；
- **不因预报永久揭示未知地形**（迷雾规则不变）。

# 追加问题 2：沙尘暴装备按钮显示不完整

**修复**：把按钮做成**不可能裁切**的一组约束——

- `flex: 1 1 160px` + `flex-wrap: wrap`：装得下就并排，装不下就**整块换行**，绝不横向挤压；

  空间不足时**换行并把按钮变高**，而不是裁字；
- 显式禁止 `text-overflow: ellipsis`、禁止固定高度截掉第二行（`height: auto` / `max-height: none`）；
