## 1. 核心目标

玩家携带 2000 元从城市出发，在最大旅程天数内完成：
城市 → 穿越随机格子地图 → 抵达两个矿区之一 → 自行决定挖矿天数 → 沿不重复路线返回城市。
**宝石的精确单价属于"最终鉴定"结果，只有在玩家成功返城后才公布**（v0.1.2a）。
矿区本身的客观开采难度会影响其价值。

## 1.1 游戏前规则说明（v0.1.2a）

- 首次进入游戏必须经过**完整规则说明页**，点击「我已阅读规则，开始远征」后才能开局。
- 游戏过程中可随时通过顶栏「规则」按钮重新打开规则（Modal 形式，**不消耗游戏天数**）。
- 规则页覆盖：目标、地图、移动、去返程限制、时间、帐篷宿营、城市/村庄、绿洲、矿区、
  天气预报、随机事件、宝石价格、失败条件。

## 2. 时间系统

- 明确两个变量：`daysUsed`（已用天数，初始 0）与 `maxDays`（最大旅程天数，初始 42）。
  UI 显示「天数：X / Y」。
- 消耗 1 天的行为：移动 1 格、原地停留、绿洲休整、村庄打工（市集）、追回盗贼、挖矿 1 天。
- 额外损失 1 天：沙尘暴迷路、草地陷入泥沼。
- **购买天气预报包既不消耗天数，也不改变 `maxDays`**：它是纯现金支出（见 §10，v0.1.3 现金计价）。
- `daysUsed > maxDays` 立即失败；`daysUsed == maxDays` 当天成功回城仍算成功。

## 3. 阶段（Phase）

| 阶段 | 含义 |
| --- | --- |
| OUTBOUND | 去程：城市出发前往矿区入口 |
| MINING | 采矿：在矿区入口挖矿 |
| RETURN | 返程：从同一矿区入口返回城市 |
| FINISHED | 结束（胜利或失败） |

## 4. 地图（v0.1.2 核心变更）

- **m×n 二维格子地图**，尺寸**固定为 8×9（72 格）**（v0.1.2b 真人试玩测试尺寸，
  不代表永久最终值），属于游戏基础规则，不是按局随机的玩法参数。
- **城市固定左下角** `(rows-1, 0) = (7, 0)`：起点、终点、允许重复、无随机遭遇。
- **两个矿区 Mine A / Mine B** 全部位于**最右列** `col = cols-1 = 8`，行由 Seed 在
  **合法行区间内**随机：
  - 合法行 = `[0, rows-1-mineBottomForbiddenRows] = [0, 5]`；
    **禁止出现在最下方两行（row 6 / 7）** —— 城市固定在左下角时，
    矿区若刷到右下会让远征距离过短；
  - 不重合；最小行距 ≥ `mineMinRowGap = 3`
    （10×12 时为 4；缩小到 8×9 后合法行只剩 6 行，沿用 4 会让 row 2/3 完全无法出现，
    故做最小必要调整并保留"两矿区有明显纵向差异"的要求）；
  - 矿区不参与普通地形随机，无随机遭遇，天气恒晴。
- 除城市与矿区外的普通格地形**完全独立随机**（与位置、路线无关）：

| 地形 | 概率（v0.1.2a：4:3:2:1） |
| --- | --- |
| 草地 GRASS | 0.40 |
| 沙漠 DESERT | 0.30 |
| 村庄 VILLAGE | 0.20 |
| 绿洲 OASIS | 0.10 |

不存在预制安全通道、沙漠走廊或位置偏置：矿区附近不保证更危险，城市附近不保证更安全。

- 旧版 36 节点 / 59 条道路的固定路线体系已删除（node/edge/road 数据结构不再存在）。
- 同一 Seed 确定性生成完全相同的地图（地形、天气、遭遇、绿洲状态、矿区价值）。

## 5. 移动规则

- 只允许**上下左右四方向**移动，不允许斜向；每移动一格消耗 1 天。
- 禁止：越界、进入违反去返程重复规则的格子、中途返回城市、任何形式的瞬移。

## 6. 路线不可重复规则（核心规则保留）

- **去程**：普通格每格只能经过一次（被"烧掉"）；不允许中途回城；抵达任一矿区即进入 MINING。
- **返程**：不得经过去程已烧掉的普通格，返程自身也不得重复普通格。
- **豁免**：城市、当前进入的矿区。**另一个矿区不是豁免格**（返程不可进入）。
- 去程走过的普通格在返程中直接视为不可通行。

## 7. 无路可回判断与提前判负（v0.1.2a 升级）

不依赖局部邻格判断，使用 BFS 全局路径检测（`hasLegalReturnPath`）：

- 进入矿区时：若无合法返城路径 → 立即失败（`RETURN_ROUTE_SEVERED`）；
- 开始返程时：同样检测；
- 返程每次关键行动后：路线被自己封死 → 立即失败；
- 去程被围死（无任何合法移动）→ 失败（`TRAPPED`）。

**后台持续裁判（`evaluateViability`）**：每次行动结算后判断——
以当前足迹、当前阶段与剩余时间，是否仍存在一条符合全部规则、
能在剩余时间内完成的合法方案：

- 不存在任何合法完成路线 → 失败（`NO_LEGAL_ROUTE`）；
- 最短合法完成所需时间（乐观下界）> 剩余允许时间 → 失败（`INSUFFICIENT_TIME`）。

裁判使用保守下界（去程距离忽略新去程对返程的烧格影响），绝不误判。

**v0.1.2b 修正**：裁判与 `hasLegalReturnPath` 的返程通行口径必须与 `getLegalMoves`
完全一致 —— **当前矿区豁免、可穿透；只有另一座矿区不可作为通路**。
修正前两座矿区都被当作不可通行节点，会把「离开矿区后必须借道当前矿区绕行」的合法局面
误判成 `NO_LEGAL_ROUTE`；在 8×9 这类小地图上，去程沿一整行推进会留下"烧格墙"，
这种局面非常常见，因此该误判必须修掉（回归测试见 tests/earlyFailure.test.ts）。
`minimumLegalCompletionDays` 属于内部裁判信息，**正常 UI 绝不显示**最短剩余天数、
最短路线或算法结果；失败信息只说明原因类别（见 §18）。

## 8. 地图合法性约束

生成时验证：城市与每个矿区之间存在**两条内部普通格完全不重合的路径**
（Menger 单点删除校验：删去任意一个非端点格后仍连通）。
不满足时以 `seed#mapRetryN` 确定性重试生成（上限 `gameConfig.map.maxRetries = 200`），
保证同一个主 Seed 最终仍得到相同地图。

矿区价值评估阶段（§9）若贪心搜索找不到合法往返组合，同样触发确定性重试。

## 9. 矿区动态价值（v0.1.2a 修订：最短合法往返方案基准）

旧版南 100 / 中 160 / 北 240 固定价格已废弃；v0.1.2 的复杂加权公式（距离×2 +
去程风险×0.8 + 返程风险×1.0 + 走廊稀缺 + 天气负载）也已废除。

### 9.1 价格基准（正式定义）

**宝石单位价格基数 = 该矿区「最短合法往返方案」的客观危险程度。**

- 合法往返方案：城市 → Mine → 城市，四方向移动、去程普通格不重复、
  返程不用去程普通格且自身不重复、城市与该矿区为豁免端点、
  不得穿过另一个矿区；
- **主准则**：完整往返总长度最短（节点拆分最小费用流，精确求解）；
- **同长度**：取其中客观危险程度最低的一条作为价格基准
  （确定性次准则：正值化格风险累计最低）；
- 这代表：用最合理、最高效的方式开采该矿，仍需承担的最低客观危险。

### 9.2 价格公式

```
difficultyScore = 最短合法往返方案的格风险和（沙漠 4.5 / 草地 7.0 / 村庄 -3.5 / 绿洲 -2.5）
gemPrice = clamp(140, 320, round((base 140 + difficultyScore × scale 2.0) × jitter))
jitter ∈ [0.90, 1.10]（宝石质量 / 矿脉差异 / 市场鉴定，只作小幅修正）
```

品质随机只能小幅修正，不能盖过往返方案的风险差异。

#### 9.2.1 v0.1.2b 重新标定说明

地图从 10×12 缩到 8×9 后，客观难度分整体被压缩（往返 20~30 天、普通格 18~28 个，
难度分 p10/中位/p90 = 16/40.5/63.5，旧地图约 120~230）。沿用旧参数会让
**39.5%** 的矿区被钉在价格下限 80 元/kg、平均单价只有 100 元/kg，
合理成功远征常常覆盖不了装备支出（真人试玩反馈）。

标定做法（**不是**机械上调、**不是**全局保底）：

- 保留斜率 `scale = 2.0`（每 1 点客观难度 = 2 元/kg），矿区之间的相对差异不变；
- 截距 `base 10 → 140`，等于把锚点重新钉在新区间的下限（难度 0 → 140 元/kg）；
- 下限 `80 → 140`；上限 `320` **保持不变**（不因小地图抬高上限）。

结果：难度 p10/中位/p90 → **172 / 221 / 267 元/kg**，触底 1.75%、触顶 0.21%。
3000 局标定中合理玩家（ReasonablePlayerBot）成功局盈利占比 99.96%、
p10 净收益 +2018 元；而「只挖 1 天」「不买装备」「把本金全砸在无用装备上」依旧明确亏损。
完整扫描见 docs/BALANCE_LOG.md 与 reports/economy-calibration.md。

### 9.3 防刷保证与价格保密

- 价格**绝对不**依赖玩家实际行为：绕路、多走沙漠/草地、受伤、用帐篷/指南针、
  停留天数等一律不影响已生成的价格。系统基准 Risk=50 时玩家绕路实际 Risk=100，
  价格仍按 50 计算。
- **游戏全程不显示矿区精确单价**（开局/途中/到达/挖矿均不显示）。
  只有成功完成合法往返把宝石带回城市后，结算页才显示「最终鉴定单价」。
- 开发/仿真模式可读取 `difficultyScore` 与 `detail`，生产 UI 全部隐藏。

## 10. 天气预报（现金计价；v0.1.3 Forecast Economy Autonomous Lab 结论）

旧版「花 1 天查看未来 3 天」以及 v0.1.2 的「`maxDays - 1` 换 3 次预报」都已废除。
现行机制为**现金计价 + 单日局部预报 + 可储存次数**：

- 初始剩余预报次数 0。
- **购买天气预报包**：`cash -= forecast.packPrice`，获得 `forecast.chargesPerPack` 次预报，
  购买时立即自动使用 `forecast.autoUseOnPurchase` 次并显示预报；
  已有储存次数则累加。**最大旅程天数完全不变**（`forecast.maxDaysCost = 0`）。
- **不再有「购买必败检查」**：成本是现金而不是天数，因此不存在「买了就走不完」的情况；
  唯一限制是现金不足（按钮禁用并提示「资金不足」，不允许负现金）。
- **储存**：次数不过期、不随天数减少、不因移动消失、可带入返程、
  可在任何正常行动阶段主动使用；使用不消耗天数/金钱/耐力（成本已在购买时支付）。
- **内容**：每次只预报**下一天**，不预报更远。
- **空间范围**：玩家当前格 + 周围一圈 8 邻域（内部 9 格 / 边缘 6 格 / 角落 4 格）。
- **UI 必须是「局部天气地图」，不是天气列表（v0.1.2b 追加修复）**：
  每张天气卡片的位置**只**由相对玩家的偏移 `(deltaRow, deltaCol)` 决定，映射到固定的 3×3：
  ```
  (-1,-1) 西北   (-1,0) 北   (-1,+1) 东北
  ( 0,-1) 西     ( 0,0) 当前格 ( 0,+1) 东
  (+1,-1) 西南   (+1,0) 南   (+1,+1) 东南
  ```
  - 内部格 = 完整 3×3；上/下边缘 = 2×3；左/右边缘 = 3×2；四个角 = 2×2；
  - **地图边界外的方向直接不存在该卡片**，且**绝不允许按数组/flex/grid 自动补位**——
    否则玩家在 (7,0) 时 `(7,1)` 会被挤到第三行，方向关系被破坏（真人试玩已确认的问题）；
  - 实现上用固定 3×3 网格 + 显式 `grid-row = dr+2` / `grid-column = dc+2` 定位，
    越界位置留空；引擎在 `ForecastCell` 上直接下发 `dr` / `dc`，UI 不看数组下标；
  - 卡片内容不变：方位名 + 坐标 + 地形/未知 + 天气 + 当前格标识；
  - 未知地形仍然只显示「未知」，不会因为预报而永久揭示（迷雾规则不变）。
- **与战争迷雾的关系**：未知格仍显示坐标与天气（这本身就是情报），
  但不把该格地形永久揭示为已探索。
- **只预测自然天气（v0.1.2a）**：天气预报绝对不能显示或暗示盗贼、商队、
  繁荣市集、牧民等人为 Encounter。即使 Encounter 已按 Seed 预生成，
  玩家也无法通过天气预报获知。Weather 与 Encounter 严格分离。
- UI 显示「剩余天气预报次数」，规则页与开始页文案全部从 `gameConfig.forecast.*` 读取，禁止硬编码。

### 10.1 为什么改成现金计价（实验依据）

v0.1.2 的 `maxDays - 1` 计价有一个数学上无法回避的问题：
**天气预报的收益单位是「宝石 kg / 体力点」，而它的价格单位是「天」**，
两者之间没有稳定兑换率，于是无论怎么调「每包几次」，预报在仿真里始终是净负收益
（过夜实验：ForecastBot EV 比同配置对照低 866～1025 元）。

v0.1.3 改为现金计价后，预报直接与**帐篷 / 指南针 / 途中补给**竞争同一笔现金，
才可能形成「有时值得买、有时不值得买」的真实取舍。
具体标定过程（`packPrice` × `chargesPerPack` 网格 + 邻域搜索 + 大样本验证）
与最终取值写在 `reports/forecast-autolab/FORECAST_5H_AUTOLAB_REPORT.md`。


## 11. 原地停留与宿营（v0.1.2a 重做）

原地停留按所在格分为**安全停留**与**野外宿营**两类：

### 11.1 城市（安全停留点）

- 允许无限停留：`daysUsed += 1`；不需要帐篷、不需要金钱；
- 不获得耐力、收益或其他奖励。玩家可在出发前等待时机。

### 11.2 村庄（安全住宿点）

- 允许无限停留：`daysUsed += 1`；不需要帐篷、无住宿费；
- 不自动恢复耐力、不重复刷新 Encounter、无其他奖励。
- 「免费」仅指不消耗金钱与帐篷，时间照常流逝。

### 11.3 野外宿营（DESERT / GRASS / OASIS / 矿区空等）

- 必须拥有帐篷；玩家必须**明确选择一顶具体帐篷**：
  `daysUsed += 1` 且 `selectedTent.durability -= 1`；
- 没有帐篷时**禁止**在野外主动停留（不允许无帐篷强行露宿）；
- 宿营当天的天气仍正常结算（例如沙漠沙尘暴 Modal）；
- 宿营不赚钱、不回血、不获得宝石、不重新抽取遭遇、不自动触发绿洲恢复。
- **矿区空等**属于野外宿营：需要帐篷、耐久 -1（正常挖矿不消耗帐篷）。

### 11.4 帐篷逐顶管理（正式机制，v0.1.2b：稳定唯一 ID）

- 每顶帐篷拥有**稳定唯一标识** `id = tent-001 / tent-002 / …`（单调递增、绝不复用）
  与独立剩余耐久：`Tent A 3/3、Tent B 1/3`（禁止合并为总耐久）；
- 展示名由 ID 派生（tent-001 → Tent A），**不随列表位置变化**：
  帐篷被消耗/报废、列表重排后，玩家看到的编号始终指向同一顶帐篷；
- **任何消耗帐篷的场景（野外宿营、沙尘暴、草地暴雨、绿洲修整、矿区等待）
  都必须由玩家自行选择具体哪一顶**；系统不得自动选择最新/最低耐久/随机；
- **UI 与引擎之间只传 TentId，绝不传 array index**：
  帐篷会被消耗或整顶报废导致列表重排，下标会指向错误的帐篷
  （真人试玩 P0：多顶帐篷时后两顶点不动 / 选错帐篷）；
- 价格 400 元、最大耐久 3（每顶 3 次沙漠耐久）不变。

## 15. 采矿

- 进入矿区后每天挖 2 kg，玩家自行决定挖几天；矿区安全（无天气、无遭遇、无耐力伤害），
  **正常挖矿不消耗帐篷**；
- 矿区"什么都不做"的等待属于野外宿营：需要帐篷、耐久 -1（见 §11.3）；

### 15.1 负重返程（v0.1.4 正式机制；Autonomous Mechanism Evolution Lab 结论）

**规则（玩家视角，1~2 句）**：
> 宝石背得越多，驼队穿越沙漠越吃力：**载重超过 24kg 之后，每多背 6kg，返程每穿越 1 格沙漠就多耗 1 天**
> （单格最多 +1 天）。觉得太重，可以随时**丢弃宝石**减负——丢弃不消耗时间。

**数值**：`loadReturn = { thresholdKg: 24, stepKg: 6, maxExtraPerDesertTile: 1, allowDrop: true, dropStepKg: 4 }`。

**为什么需要它（实验依据）**：
- 落盘前「到矿后继续挖还是返程」几乎不存在抉择：矿区零风险、多挖一天零成本、提前返程零收益，
  **多挖永远严格优于早退**，玩家唯一的上限是返程时限。28k 局配对仿真显示：
  与当前正式基线相比，采矿决策改变率 = **0%**，即任何地图、任何风险、任何资源状态下
  玩家的采矿时长都由同一条时间规则决定。
- 该机制把「多挖一天」与「返程变贵」直接绑定：多挖 → 载重上升 → 返程更慢/更贵 → 需要丢货或早退，
  于是采矿时长第一次成为真正的取舍。**25k 局大样本配对结果：采矿决策改变率 82%，且没有支配策略。**

**与上一轮被否决方案的差别（重要）**：
上一轮否决了「携带 ≥X kg，每 5 步额外耐力 -1」。该模型只是**纯加伤害**，不改变任何决策
（玩家无法通过任何选择避免它，只是把失败率整体抬高）。
本机制改为**改变返程的代价结构**，并给玩家一个明确的补救动作（丢货），因此它改变的是**选择**而不是**伤害**。

**为什么是分级而不是一刀切阈值**：一刀切（超阈值恒定 +1 天）会让「丢货」变成全有或全无的巨额决策
（必须一口气丢掉十几 kg 才有效），实测 `dropRate = 0%` —— 按钮变成死按钮。
改为「每多背 stepKg 多 1 天」后，丢弃一小步即可立刻换回效率，边际权衡才真实存在（实测丢货率 35%）。

### 15.2 已知的机制边界：返程**路线**选择仍不可达

「按地形选返程路线」在本游戏的规则下**结构上不可能成立**，本轮已用实验证伪：
返程规定「不得重走去程普通格」，而被探索过的格子恰恰只有去程走过的那批，
所以返程每一步都必然踏进战争迷雾 —— 任何以地形为代价依据的机制都无法影响路线决策。
实测：所有地形依赖型机制的 `returnDecisionChange` 恒为 **0.00%**；即使额外加「抵达矿区时揭示周边 1 圈地形」
（M13），也只把路线改变率抬到 **6%**，代价是把 EV 压到基线的 64%。因此本轮**不**推广路线类机制，
并把它列为下一轮的前置设计问题（可选方向：公开返程走廊的地形情报）。

## 17. 金钱与结算

- 结算显示：daysUsed / maxDays、去程/挖矿/返程天数、天气预报包购买数、

### 17.1 远征结果与经济结果必须分开（v0.2.0 起）

「成功返城」与「赚钱」是两件事：成功返城但亏损是一种**合法且真实**的结局，
不是游戏失败。结算页因此把两者分开展示，并给出完整瀑布账目。

### 17.2 会计恒等式（v0.3.0 硬门禁，§35）

每一局都必须能对账，任何一笔钱都不能凭空出现或消失：

```
finalCash = initialCash
          − 装备支出 − 天气预报 − 村庄服务 − 求援当场支付
          + 途中事件净变动
          + 宝石销售毛收入 − 逾期折价
          − 结算期费用（求援结算费 + 远征运营成本 + 运输费 + 佣金 + 鉴定费）
```

`src/game/rules/settlement.ts` 是**唯一真源**：UI、仿真、实验报告全部读它，
不允许任何一侧自己复刻一遍公式。

### 17.3 经济机制族（v0.3.0，默认按 Promotion Gate 决定是否开启）

| 族 | 一句话规则 | 为什么存在 |
|---|---|---|
| 延期求援 | 求援当场不收钱，回城结算时从宝石收入里扣一笔债务/抽成 | 上一轮「当场付 400 元」撞上可负担性悬崖（成功局手上最多约 550 元），结构上无法做出「成功但亏损」 |
| 远征运营成本 | 前 N 天商队包干，之后每天 X 元，回城结算 | 只有拖得久的局付钱 ⇒ 制造「多挖一天值不值」的真实边际判断 |
| 逾期折价 | 城门集市只开到第 N 天，之后回城的宝石折价卖出 | 同族候选，本轮未 Promotion |
| 运输/佣金/鉴定 | 按重量或销售额收费 | 本轮定位为 ECONOMIC_CONTROL 对照组，默认不 Promotion |

### 19.1 装备按钮文案必须完整可读（v0.1.2b 追加修复）

真人试玩确认：沙漠沙尘暴的装备选择按钮出现文字截断 / 看不全（例如
「+ 指南针（安全通过）」被裁掉后半段）。玩家必须能完整看到"点了会发生什么"。

规则：

- 所有装备选择按钮的**完整文案必须可见**：不允许截断、不允许省略号隐藏关键规则、
  不允许被 overflow 祖先裁切、不允许因为多帐篷列表而压缩到不可读；
- 按钮文本与它触发的 Action **完全同源**（同一处文案同时用于显示与行为说明）；
- **不强制单行**：宽度不足时允许换行、允许按钮变高
  （`white-space: normal` + `overflow-wrap: anywhere` + `min-width: 0`）；
  `+ 指南针` / `（安全通过）` 分两行显示是允许的，`+ 指南针（安全…` 是不允许的；
- 容器策略：`flex: 1 1 160px` + `flex-wrap: wrap` —— 装得下就并排，装不下就整块换行，
  绝不横向挤压；
- 禁止 `text-overflow: ellipsis`、禁止固定高度截掉第二行；
- Modal 内容溢出时**不再对文字做底部渐隐遮挡**（旧实现会让最后一行看起来被截断），
  只保留可点击的「↓ 下方还有选项」提示条；
- `disabled` 状态仍然完整可读（只降对比度，不裁字）。

覆盖审计（`scripts/run-browser-audit.sh stormlabels` / `stormlabels2`）逐视口检查：
1366×768、1920×1080、窄窗口、640 极窄，以及 90% / 100% / 110% 缩放；
4 顶帐篷（A 3/3、B 3/3、C 2/3、D 1/3）的每一行、以及「没有指南针」的禁用态。

## 20. 即时反馈与结果弹窗（v0.1.2b Human Playtest Fix Round 1）

真人试玩反馈：耐力下降、帐篷报废、指南针消耗、金钱变化、预报次数变化、maxDays 减少、
耐力恢复这些关键变化原先只写在右下角日志里，玩家经常没有意识到发生了资源变化。

### 20.1 规则

> **关键资源变化必须在事件结算后立即向玩家显式反馈。**

- 反馈形式：统一结果组件 `ResultModal`（`src/components/ResultModal.tsx`），
  不针对每个事件各造一套弹窗；
- 内容：`事件标题` + `发生了什么` + `资源变化（变化前 → 变化后）` + `确认按钮`；
- **一次事件同时改变多项资源 → 只弹一个综合结果**（绝不连弹三个）；
- 右下角旅途日志**继续保留**，并作为历史记录：同一事件两边同时记录（同源双写）；
- 反馈顺序：待决事件 Modal → 结果弹窗 → 天气预报 Modal（先进先出，按事件发生顺序）。

### 20.2 数据来源（引擎负责，UI 只渲染）

引擎每次结算走同一个入口 `recordResult(s, meta, mutate)`，在同处完成三件事：

1. 执行结算逻辑；
2. 对结算前后的资源快照做 diff，把**本次全部变化**合成一个
   `EventResult { title, message, changes, kind, history, outcome, defeatReason }`
   推入 `GameState.pendingResults`（UI 消费后由 `dismissPendingResult` 弹出队首）；
3. 把同一事件写入 `log`，并把那条日志快照进 `EventResult.history`。

`ResourceChange { key, label, before, after, direction }` 覆盖：

| key | 展示 |
| --- | --- |
| `tent` | `Tent A: 3/3 → 2/3`、`Tent C: 1/3 → 报废`、`Tent E（新）: 无 → 3/3` |
| `stamina` | `耐力: 5/5 → 3/5` |
| `cash` | `金钱: ¥2000 → ¥1600` |
| `gemsKg` | `宝石: 0 kg → 2 kg` |
| `compass` | `指南针: 3 → 2` |
| `forecast` | `天气预报次数: 0 → 2` |
| `maxDays` | `最大旅程天数: 42 → 41` |
| `day` | `天数: 第 12 天 → 第 13 天` |

### 20.3 什么时候弹窗（避免做成"弹窗模拟器"）

需要即时弹窗：天气伤害（高温 / 沙尘暴 / 暴雨 / 泥沼）、遭遇结果（商队 / 盗贼 / 市集 / 牧民）、
帐篷耐久变化与报废、指南针消耗、耐力变化、绿洲修整、交易与购买、天气预报购买与使用、
采矿结果、关键失败与成功。

**不**弹窗：正常移动（无天气伤害 / 无事件 / 无装备损耗），以及城市/村庄停留这类
「只推进一天时间、没有其它资源变化」的动作 —— 只更新 HUD 与日志。

### 20.4 失败原因必须明确

耐力耗尽失败时，结果弹窗会给出 `远征失败 · 耐力耗尽`，并显示 `耐力: 2/5 → 0/5`；
结算页同时给出对应的失败说明，不会只显示一个普通的 GAME OVER。

## 21. 地图排版（v0.1.2b 8×9 重排版）

- 地图尺寸（列数 / 行数）**全部**从 `gameConfig.map` 派生，代码与 CSS 中不保留旧 10×12 的任何固定值；
- 格子用 `aspect-ratio: 1/1` 保持接近正方形；
- 地图宽度 = `min(容器宽度, (可用高度 - 8px) × 列数 / 行数)`：
  由高度反推宽度，保证整张地图完整可见、不触发容器纵向滚动条；

- 地图在自己的主游戏区域（地图面板）内水平居中；右侧日志是独立侧栏，
  日志宽度变化不会牵动地图中心；
- 地图区与日志区各自占据 `.game-layout` 的独立轨道，窄窗口（≤980px）降级为单列。
