## 2026-09-14 · Human Playtest Fix Round 1 续：草地暴雨 -2 + 即时反馈 + 8×9 排版复核

第一次真人试玩修复轮里，地图 / 帐篷稳定 ID / Modal P0 / 宝石标定已经落地；
本轮把**同一轮里尚未完成的三项已确认问题**补齐，不新增玩法、不动其它数值。

### 1. 草地暴雨不使用帐篷：耐力 -1 → -2
- 真人试玩结论：硬扛暴雨的代价太轻，玩家倾向于不带帐篷赌天气，远征的张力不够。
- 数值集中到 `gameConfig.weather.grassRain.staminaLossWithoutTent = 2`，
  引擎两条路径（"没有帐篷直接结算"与"有帐篷但选择硬扛"）与 UI 文案全部读它。
- 顺手把 `heatStaminaCost` / `sandstormStaminaCost` / `rainstormStaminaCost` 三个扁平字段
  收进结构化 `gameConfig.weather.*`，删掉旧字段——避免同一数值散落两处导致调参不一致。
- 明确标注这是**本轮试玩暂定值**（不是永久数值），下一轮真人试玩可能改回 -1。
- 耐力因此归零时，结果弹窗与结算页都会明确显示「耐力耗尽」，不是普通 GAME OVER。

### 2. 即时反馈（统一 ResultModal）+ 日志双记录
- 真人试玩反馈：资源变化只写在右下角日志里，玩家经常没意识到耐力掉了、帐篷报废了。
- 引擎新增统一结算入口 `recordResult(s, meta, mutate)`，对结算前后的资源快照做 diff，
  把**一次结算的全部变化**合成 **一个** `EventResult` 推入 `GameState.pendingResults`，
  同时把同一事件写入历史日志并把那条日志快照进 `EventResult.history` —— 结构性保证"双记录"。
- 变化一律以「变化前 → 变化后」呈现（引擎算，UI 只渲染）：
  `Tent A 3/3→2/3`、`Tent C 1/3→报废`、`金钱 ¥2000→¥1600`、`耐力 5/5→3/5`、
  `最大旅程天数 42→41`、`天气预报次数 0→2`、`天数 第12天→第13天`。
- 统一 `src/components/ResultModal.tsx`：标题 + 发生了什么 + 变化清单 + 确认按钮，
  支持「确定」/ × / Esc / Footer 关闭；失败局还会给出红色「远征失败 · 耐力耗尽」横幅。
- 「不做成弹窗模拟器」的开关在引擎里：`changes` 为空（且未 `force`）时只写日志不弹窗，
  并且**只推进一天**的动作用 `onlyDay` 规则抑制；因此正常移动、城市/村庄停留都不打扰玩家。
- 反馈顺序：待决事件 Modal → 结果弹窗 → 天气预报。同一行动产生的"宿营"与"当天天气"
  两个结果按事件发生顺序（FIFO）依次确认；宿营动作把当天天气并入自己的综合结果，不重复弹。

### 3. 8×9 地图排版复核（左黑边 / 居中）
- 复核结论：左黑边来自旧 10×12 布局的固定尺寸遗留（`.grid-map { min-width: 420px }`
  = 12 列 × 34px 的硬编码），已在首轮改成 300/560 上下限 + `margin: 0 auto`。
- 本轮把它做得更彻底：CSS 与组件里**不再保留任何固定尺寸**，
  宽度 = `min(容器宽, (可用高度-8px) × 列数/行数)`，列数行数全部从 `gameConfig.map` 派生。
- 浏览器实测发现一个隐藏的居中 bug：容器 `max-height: var(--map-max-h)` 配自身 1px 边框
  会让地图高出约 2px → 容器出现纵向滚动条 → 可视宽少 15px → 地图中心相对面板中心**偏移 7.5px**。
  修正为 `max-height: calc(var(--map-max-h) + 2px)` 并在宽度里留 8px 余量后，偏差归零。
- `layout` 场景在 9 组视口/缩放组合下逐项测量：左右留白完全对称、中心偏差 0、
  格子 45~75px 接近正方形、无横向溢出、地图不被切掉、不覆盖 HUD 与日志。

### 5. 追加两项真人试玩确认的 UI 修复
- **天气预报方位**：真人截图里玩家在 (7,0)，有效格是 (6,0)(6,1)(7,0)(7,1)，
  但 UI 把 (7,1) 排到了第三行。根因是 `ForecastModal` 直接 `view.cells.map(...)`
  塞进 3 列网格，而地图边缘会裁掉越界格（左下角少了 W/SW/S 三个方向），
  剩下 4 张卡片就顺着网格**自动向前补位**，方向关系整体错位。
  修复：`ForecastCell` 增加 `dr`/`dc`，UI 用固定 3×3 + 显式行列定位，
  越界方向不渲染元素、留空补位为不可能。9 类位置（内部/四边/四角）全部实测通过。
- **沙尘暴按钮文字**：在真实 Chromium 里按 1366×768 / 1920×1080 / 窄窗口 / 640 极窄 ×
  90/100/110% 共 9 组视口逐项测量了 4 顶帐篷（A 3/3、B 3/3、C 2/3、D 1/3）的 10 个按钮。
  当前代码在这些视口下**并没有出现裁切**，但存在两个真实隐患，一并按"不可能裁切"加固：
  1. `.modal-body` 因为 `overflow-y: auto` 会隐式获得 `overflow-x: auto`，
     长文案按钮一旦超宽就会被横向裁掉（滚动条不明显），
     现在按钮改为 `flex: 1 1 160px` + 换行 + `min-width: 0` + `overflow-wrap: anywhere`，
     装不下就整块换行、变高，绝不挤压裁字；
  2. 原先 `.modal-body.is-overflowing` 有一条 18px 底部文字渐隐，
     会让滚动区最后一行看起来"被截断"——已删除，只保留可点击的滚动提示条。
  另外补上 `.btn:disabled` 的可读样式（只降对比度，不裁字）。
- 审计脚本新增 `forecast` / `stormlabels` / `stormlabels2` 三个场景，
  并给 lib 增加"文案完整性"断言原语（裁切 / 遮挡 / 指针可达 / 逐字匹配 / 行数）。
