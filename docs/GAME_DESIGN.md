## 1. 核心目标

玩家携带 2000 元从城市出发，在最大旅程天数内完成：
城市 → 穿越随机格子地图 → 抵达两个矿区之一 → 自行决定挖矿天数 → 沿不重复路线返回城市。
**宝石的精确单价属于"最终鉴定"结果，只有在玩家成功返城后才公布**（v0.1.2a）。
矿区本身的客观开采难度会影响其价值。

## 1.1 游戏前规则说明（v0.1.2a）

- 首次进入游戏必须经过**完整规则说明页**，点击「我已阅读规则，开始远征」后才能开局。
- 游戏过程中可随时通过顶栏「规则」按钮重新打开规则（Modal 形式，**不消耗游戏天数**）。
- 规则页覆盖：目标、地图、移动、去返程限制、时间、帐篷宿营、城市/村庄、绿洲、矿区、
  天气预报、随机事件、宝石价格、失败条件。

## 2. 时间系统

- 明确两个变量：`daysUsed`（已用天数，初始 0）与 `maxDays`（最大旅程天数，初始 42）。
  UI 显示「天数：X / Y」。
- 消耗 1 天的行为：移动 1 格、原地停留、绿洲休整、村庄打工（市集）、追回盗贼、挖矿 1 天。
- 额外损失 1 天：沙尘暴迷路、草地陷入泥沼。
- **购买天气预报包不消耗天数，而是永久 `maxDays - 1`**（见 §10）。
- `daysUsed > maxDays` 立即失败；`daysUsed == maxDays` 当天成功回城仍算成功。

## 3. 阶段（Phase）

| 阶段 | 含义 |
| --- | --- |
| OUTBOUND | 去程：城市出发前往矿区入口 |
| MINING | 采矿：在矿区入口挖矿 |
| RETURN | 返程：从同一矿区入口返回城市 |
| FINISHED | 结束（胜利或失败） |

## 4. 地图（v0.1.2 核心变更）

- **m×n 二维格子地图**，尺寸**固定为 8×9（72 格）**（v0.1.2b 真人试玩测试尺寸，
  不代表永久最终值），属于游戏基础规则，不是按局随机的玩法参数。
- **城市固定左下角** `(rows-1, 0) = (7, 0)`：起点、终点、允许重复、无随机遭遇。
- **两个矿区 Mine A / Mine B** 全部位于**最右列** `col = cols-1 = 8`，行由 Seed 在
  **合法行区间内**随机：
  - 合法行 = `[0, rows-1-mineBottomForbiddenRows] = [0, 5]`；
    **禁止出现在最下方两行（row 6 / 7）** —— 城市固定在左下角时，
    矿区若刷到右下会让远征距离过短；
  - 不重合；最小行距 ≥ `mineMinRowGap = 3`
    （10×12 时为 4；缩小到 8×9 后合法行只剩 6 行，沿用 4 会让 row 2/3 完全无法出现，
    故做最小必要调整并保留"两矿区有明显纵向差异"的要求）；
  - 矿区不参与普通地形随机，无随机遭遇，天气恒晴。
- 除城市与矿区外的普通格地形**完全独立随机**（与位置、路线无关）：

| 地形 | 概率（v0.1.2a：4:3:2:1） |
| --- | --- |
| 草地 GRASS | 0.40 |
| 沙漠 DESERT | 0.30 |
| 村庄 VILLAGE | 0.20 |
| 绿洲 OASIS | 0.10 |

不存在预制安全通道、沙漠走廊或位置偏置：矿区附近不保证更危险，城市附近不保证更安全。

- 旧版 36 节点 / 59 条道路的固定路线体系已删除（node/edge/road 数据结构不再存在）。
- 同一 Seed 确定性生成完全相同的地图（地形、天气、遭遇、绿洲状态、矿区价值）。

## 5. 移动规则

- 只允许**上下左右四方向**移动，不允许斜向；每移动一格消耗 1 天。
- 禁止：越界、进入违反去返程重复规则的格子、中途返回城市、任何形式的瞬移。

## 6. 路线不可重复规则（核心规则保留）

- **去程**：普通格每格只能经过一次（被"烧掉"）；不允许中途回城；抵达任一矿区即进入 MINING。
- **返程**：不得经过去程已烧掉的普通格，返程自身也不得重复普通格。
- **豁免**：城市、当前进入的矿区。**另一个矿区不是豁免格**（返程不可进入）。
- 去程走过的普通格在返程中直接视为不可通行。

## 7. 无路可回判断与提前判负（v0.1.2a 升级）

不依赖局部邻格判断，使用 BFS 全局路径检测（`hasLegalReturnPath`）：

- 进入矿区时：若无合法返城路径 → 立即失败（`RETURN_ROUTE_SEVERED`）；
- 开始返程时：同样检测；
- 返程每次关键行动后：路线被自己封死 → 立即失败；
- 去程被围死（无任何合法移动）→ 失败（`TRAPPED`）。

**后台持续裁判（`evaluateViability`）**：每次行动结算后判断——
以当前足迹、当前阶段与剩余时间，是否仍存在一条符合全部规则、
能在剩余时间内完成的合法方案：

- 不存在任何合法完成路线 → 失败（`NO_LEGAL_ROUTE`）；
- 最短合法完成所需时间（乐观下界）> 剩余允许时间 → 失败（`INSUFFICIENT_TIME`）。

裁判使用保守下界（去程距离忽略新去程对返程的烧格影响），绝不误判。

**v0.1.2b 修正**：裁判与 `hasLegalReturnPath` 的返程通行口径必须与 `getLegalMoves`
完全一致 —— **当前矿区豁免、可穿透；只有另一座矿区不可作为通路**。
修正前两座矿区都被当作不可通行节点，会把「离开矿区后必须借道当前矿区绕行」的合法局面
误判成 `NO_LEGAL_ROUTE`；在 8×9 这类小地图上，去程沿一整行推进会留下"烧格墙"，
这种局面非常常见，因此该误判必须修掉（回归测试见 tests/earlyFailure.test.ts）。
`minimumLegalCompletionDays` 属于内部裁判信息，**正常 UI 绝不显示**最短剩余天数、
最短路线或算法结果；失败信息只说明原因类别（见 §18）。

## 8. 地图合法性约束

生成时验证：城市与每个矿区之间存在**两条内部普通格完全不重合的路径**
（Menger 单点删除校验：删去任意一个非端点格后仍连通）。
不满足时以 `seed#mapRetryN` 确定性重试生成（上限 `gameConfig.map.maxRetries = 200`），
保证同一个主 Seed 最终仍得到相同地图。

矿区价值评估阶段（§9）若贪心搜索找不到合法往返组合，同样触发确定性重试。

## 9. 矿区动态价值（v0.1.2a 修订：最短合法往返方案基准）

旧版南 100 / 中 160 / 北 240 固定价格已废弃；v0.1.2 的复杂加权公式（距离×2 +
去程风险×0.8 + 返程风险×1.0 + 走廊稀缺 + 天气负载）也已废除。

### 9.1 价格基准（正式定义）

**宝石单位价格基数 = 该矿区「最短合法往返方案」的客观危险程度。**

- 合法往返方案：城市 → Mine → 城市，四方向移动、去程普通格不重复、
  返程不用去程普通格且自身不重复、城市与该矿区为豁免端点、
  不得穿过另一个矿区；
- **主准则**：完整往返总长度最短（节点拆分最小费用流，精确求解）；
- **同长度**：取其中客观危险程度最低的一条作为价格基准
  （确定性次准则：正值化格风险累计最低）；
- 这代表：用最合理、最高效的方式开采该矿，仍需承担的最低客观危险。

### 9.2 价格公式

```
difficultyScore = 最短合法往返方案的格风险和（沙漠 4.5 / 草地 7.0 / 村庄 -3.5 / 绿洲 -2.5）
gemPrice = clamp(140, 320, round((base 140 + difficultyScore × scale 2.0) × jitter))
jitter ∈ [0.90, 1.10]（宝石质量 / 矿脉差异 / 市场鉴定，只作小幅修正）
```

品质随机只能小幅修正，不能盖过往返方案的风险差异。

#### 9.2.1 v0.1.2b 重新标定说明

地图从 10×12 缩到 8×9 后，客观难度分整体被压缩（往返 20~30 天、普通格 18~28 个，
难度分 p10/中位/p90 = 16/40.5/63.5，旧地图约 120~230）。沿用旧参数会让
**39.5%** 的矿区被钉在价格下限 80 元/kg、平均单价只有 100 元/kg，
合理成功远征常常覆盖不了装备支出（真人试玩反馈）。

标定做法（**不是**机械上调、**不是**全局保底）：

- 保留斜率 `scale = 2.0`（每 1 点客观难度 = 2 元/kg），矿区之间的相对差异不变；
- 截距 `base 10 → 140`，等于把锚点重新钉在新区间的下限（难度 0 → 140 元/kg）；
- 下限 `80 → 140`；上限 `320` **保持不变**（不因小地图抬高上限）。

结果：难度 p10/中位/p90 → **172 / 221 / 267 元/kg**，触底 1.75%、触顶 0.21%。
3000 局标定中合理玩家（ReasonablePlayerBot）成功局盈利占比 99.96%、
p10 净收益 +2018 元；而「只挖 1 天」「不买装备」「把本金全砸在无用装备上」依旧明确亏损。
完整扫描见 docs/BALANCE_LOG.md 与 reports/economy-calibration.md。

### 9.3 防刷保证与价格保密

- 价格**绝对不**依赖玩家实际行为：绕路、多走沙漠/草地、受伤、用帐篷/指南针、
  停留天数等一律不影响已生成的价格。系统基准 Risk=50 时玩家绕路实际 Risk=100，
  价格仍按 50 计算。
- **游戏全程不显示矿区精确单价**（开局/途中/到达/挖矿均不显示）。
  只有成功完成合法往返把宝石带回城市后，结算页才显示「最终鉴定单价」。
- 开发/仿真模式可读取 `difficultyScore` 与 `detail`，生产 UI 全部隐藏。

## 10. 天气预报（单日局部 + 可储存次数；v0.1.2a 补充保密规则）

旧版「花 1 天查看未来 3 天」已废除。改为**单日局部预报 + 可储存次数**：

- 初始剩余预报次数 0。
- **购买天气预报包**：成本不是金钱，而是 **maxDays 永久 -1**（牺牲一天旅程预算）；
  获得 3 次预报，购买时立即自动使用 1 次 → 购买完成剩余 2 次，并立即显示预报。
  例：`0/42 → 0/41`，`12/41 → 12/40`；已有储存次数则累加（1 + 3 - 1 = 3）。
- **购买必败检查（v0.1.2a）**：购买前后台检查是否会导致本局数学上无法完成；
  若会则禁止购买并提示「此次购买会导致剩余时间不足以完成旅程」
  （不显示内部最短天数）。
- **储存**：次数不过期、不随天数减少、不因移动消失、可带入返程、
  可在任何正常行动阶段主动使用；使用不消耗天数/金钱/耐力（成本已在购买时支付）。
- **内容**：每次只预报**下一天**，不预报更远。
- **空间范围**：玩家当前格 + 周围一圈 8 邻域（内部 9 格 / 边缘 6 格 / 角落 4 格）。
- **与战争迷雾的关系**：未知格仍显示坐标与天气（这本身就是情报），
  但不把该格地形永久揭示为已探索。
- **只预测自然天气（v0.1.2a）**：天气预报绝对不能显示或暗示盗贼、商队、
  繁荣市集、牧民等人为 Encounter。即使 Encounter 已按 Seed 预生成，
  玩家也无法通过天气预报获知。Weather 与 Encounter 严格分离。
- UI 显示「剩余天气预报次数」。

## 11. 原地停留与宿营（v0.1.2a 重做）

原地停留按所在格分为**安全停留**与**野外宿营**两类：

### 11.1 城市（安全停留点）

- 允许无限停留：`daysUsed += 1`；不需要帐篷、不需要金钱；
- 不获得耐力、收益或其他奖励。玩家可在出发前等待时机。

### 11.2 村庄（安全住宿点）

- 允许无限停留：`daysUsed += 1`；不需要帐篷、无住宿费；
- 不自动恢复耐力、不重复刷新 Encounter、无其他奖励。
- 「免费」仅指不消耗金钱与帐篷，时间照常流逝。

### 11.3 野外宿营（DESERT / GRASS / OASIS / 矿区空等）

- 必须拥有帐篷；玩家必须**明确选择一顶具体帐篷**：
  `daysUsed += 1` 且 `selectedTent.durability -= 1`；
- 没有帐篷时**禁止**在野外主动停留（不允许无帐篷强行露宿）；
- 宿营当天的天气仍正常结算（例如沙漠沙尘暴 Modal）；
- 宿营不赚钱、不回血、不获得宝石、不重新抽取遭遇、不自动触发绿洲恢复。
- **矿区空等**属于野外宿营：需要帐篷、耐久 -1（正常挖矿不消耗帐篷）。

### 11.4 帐篷逐顶管理（正式机制，v0.1.2b：稳定唯一 ID）

- 每顶帐篷拥有**稳定唯一标识** `id = tent-001 / tent-002 / …`（单调递增、绝不复用）
  与独立剩余耐久：`Tent A 3/3、Tent B 1/3`（禁止合并为总耐久）；
- 展示名由 ID 派生（tent-001 → Tent A），**不随列表位置变化**：
  帐篷被消耗/报废、列表重排后，玩家看到的编号始终指向同一顶帐篷；
- **任何消耗帐篷的场景（野外宿营、沙尘暴、草地暴雨、绿洲修整、矿区等待）
  都必须由玩家自行选择具体哪一顶**；系统不得自动选择最新/最低耐久/随机；
- **UI 与引擎之间只传 TentId，绝不传 array index**：
  帐篷会被消耗或整顶报废导致列表重排，下标会指向错误的帐篷
  （真人试玩 P0：多顶帐篷时后两顶点不动 / 选错帐篷）；
- 价格 400 元、最大耐久 3（每顶 3 次沙漠耐久）不变。

## 12. 遭遇（按格预生成；v0.1.2a 概率 35%）

- 所有普通格的遭遇在**地图生成阶段按 Seed 预生成**，每格每局最多触发一次
  （通常在首次进入时）；原地停留/等待不重新抽取。
- 基础触发概率 `gameConfig.encounter.baseProbability = 0.35`（v0.1.2a 由 25% 上调）。
- 地形事件池：

| 地形 | 触发后事件 |
| --- | --- |
| 沙漠 | 商队（二选一：300 元二手帐篷 / 免费情报） |
| 村庄 | 盗贼 50% / 繁荣市集 50% |
| 草地 | 牧民指引（免费情报） |
| 绿洲 | 无额外遭遇（干涸是绿洲自身状态，Seed 预生成，概率 0.20） |
| 城市 / 矿区 | 无随机遭遇 |

- 天气与遭遇严格分离、可同日叠加，先天气后遭遇。
- 情报揭示范围：当前格**曼哈顿距离 ≤2** 的未知普通格（`gameConfig.intelRevealRadius`）。

## 13. 战争迷雾

- 初始可见：城市、两个矿区（含收购价）；普通格显示 `?`。
- 玩家第一次进入普通格 → 永久揭示地形；情报揭示的格子同样可见（不带永久探索含义的区分保留）。
- 天气预报不改变迷雾状态。

## 14. 耐力 / 装备 / 天气效果

与 v0.1.1 一致：初始耐力 5 上限 5；帐篷 400 元（3 次沙漠耐久）、指南针 100 元；
沙尘暴四象限规则不变（使用哪顶帐篷由玩家选择）；草地暴雨整顶报废所选帐篷；
高温 -1 耐力；泥沼额外 +1 天。
城市与村庄可购买装备，繁荣市集当次访问八折（320/80）。

### 14.1 绿洲（v0.1.2a：区分"停留"与"修整"）

| 行为 | 条件 | 消耗 | 效果 |
| --- | --- | --- | --- |
| 有水绿洲 · **修整** | 有水 + 拥有帐篷 + 未用过修整次数 | 1 天 + 所选帐篷耐久 -1 | 耐力 +1（上限 5） |

## 15. 采矿

- 进入矿区后每天挖 2 kg，玩家自行决定挖几天；矿区安全（无天气、无遭遇、无耐力伤害），
  **正常挖矿不消耗帐篷**；
- 矿区"什么都不做"的等待属于野外宿营：需要帐篷、耐久 -1（见 §11.3）；
- 返程必须从进入的同一矿区开始；进入矿区时不显示价格（v0.1.2a）。

## 16. 路线风险评分（仅供统计，不影响售价）

保留 v0.1.1 的路线风险评分与星级（★★~★★★★★），仅用于结算展示与仿真统计。
格风险系数：沙漠 4.5、草地 7.0、村庄 -3.5、绿洲 -2.5。

## 17. 金钱与结算

- 初始现金 2000；结算公式与 v0.1.1 一致（销售额 = 宝石 × 鉴定单价，净收益 = 最终资产 - 2000）。
- 结算显示：daysUsed / maxDays、去程/挖矿/返程天数、天气预报包购买数、
  宝石重量、**最终鉴定单价**（唯一公布精确价格的时机）等。

## 18. 胜负条件

| 条件 | 结果 |
| --- | --- |
| `daysUsed <= maxDays` 时返回城市（带宝石） | 胜利 |
| 任何操作后 `daysUsed > maxDays` | 失败（超时） |
| 耐力归零 | 失败 |
| 返程不存在合法回城路径 / 进矿即被封 / 去程被围死 | 失败（路线中断） |
| 已不存在任何合法完成路线（提前判负） | 失败（`NO_LEGAL_ROUTE`） |
| 剩余时间已无法合法完成旅程（提前判负） | 失败（`INSUFFICIENT_TIME`） |

失败信息必须**明确说明原因**（路线被切断 / 时间不足 / 耐力耗尽 / 超时），
不允许只显示 GAME OVER；可以说明"时间已经不足"，
但不透露"至少还需要 N 天"等后台裁判数值。

## 19. Modal 可退出性（P0 修复）

- 所有信息类 Modal：最大高度受视口约束（`max-height: min(88vh, 100%)`）、Header 固定、
  `×` 永远可见、支持 Esc、Footer 提供关闭按钮、内容过多时仅内部滚动。
- 事件类 Modal（必须决断）：不提供关闭，但选项永远可达，不允许任何无法退出的状态。
- **v0.1.2b P0 修复（多顶帐篷后部按钮点不到）**：
  - 根因：事件 Modal 内容超出 `max-height` 后，位于折叠线以下的按钮落在
    `.modal-body` 的裁剪区之外，指针命中落到 `.modal-backdrop` / 视口外，
    在矮窗口（真人试玩环境）下表现为"前两顶帐篷能点、后两顶点不动"；
  - 修复：Modal 高度上限改为 `min(88vh, 100%)` 且 `.modal-backdrop` padding 收敛，
    保证 Modal 永不超出视口；逐顶帐篷选项改为紧凑行布局（把选项列表高度压到约 1/3）；
    内容仍溢出时**必须**显示可点击的「↓ 下方还有选项」滚动提示条（并配合底部渐隐）；
  - 规则页同理：规则正文独立滚动，确认按钮固定在滚动区之外。
  - 回归测试：tests/tentSelection.test.ts（引擎侧 4 顶帐篷全场景）+ 
    scripts/run-browser-audit.sh（浏览器侧逐按钮指针命中审计）。
